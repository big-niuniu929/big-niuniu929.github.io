# 个人项目作品集

一个**零框架、零构建依赖**的静态作品集：手写 HTML / CSS / 原生 JS，数据由 JSON 驱动，`node assets/build.mjs` 生成页面。

目的不是「展示我做过的项目」，而是**让每个数字都能被追问到底**。

---

## 这个仓库最特殊的地方：数字口径

这里的每个关键数字后面都跟一个标记：

| 标记 | 含义 |
|---|---|
| **实测** | 有原始记录、可复现、可重跑 |
| **估算** | 基数可查，但带假设（假设写在数字旁边） |
| 推算 | 由「实测」与「估算」相减或相乘得出（推算链写清楚） |
| 待核实 | 有这个东西，但缺原始凭证——所以标出来，而不是删掉 |

为什么这么做：**造假的人没有「估算」和「实测」的区别，他只有一个数字。**

把四种状态混在一起的简历，你无法判断哪句是真的；把四种状态分开标注的简历，你至少知道该信到哪一层。代价是数字看起来没那么大，收益是**每一个数字都经得起追问**。

例如「每轮省约 2 小时 36 分」这一条，拆开是：

- 自动化单轮 `23 分 42 秒` — **实测**，2 个账号 × 约 140 个 SKU，掐表
- 人工基线 `约 3 小时` — **估算**，同一流程手动操作，本人实操回忆，非掐表
- 两者相减 — **推算**，假设处理的是同一批 SKU

如果愿意，可以把「约 3 小时」换成精确值、把「推算」变成「实测」——但那需要真的再掐一次表。**没掐之前，就写「估算」。**

## 目录结构

```
├── index.html            首页（项目卡由 build.mjs 注入）
├── method.html           我怎么管理口径 / 我怎么和 AI 协作
├── work/
│   ├── price-patrol.html 项目详情页：价格巡检与三合一平台
│   ├── cs-quality.html   项目详情页：全量客服质检系统
│   ├── jianhe.html       项目详情页：简核 · 落笔
│   ├── gym-bd.html       项目详情页：校区健身卡分销
│   ├── pdd-store.html    项目详情页：拼多多百货店铺 0→1
│   ├── weiguang.html     项目详情页：微光
│   └── ai-interviewer.html 项目详情页：Ai 面试官
├── data/
│   ├── projects.json     唯一数据源：项目元信息与指标
│   └── numbers.json      全局口径总表：数字 → 标记 → 口径 → 时间窗 → 来源
└── assets/
    ├── style.css         设计系统（CSS 变量 + 组件，零圆角零阴影）
    ├── app.js            筛选 / 滚动淡入 / 导航高亮
    └── build.mjs         纯 Node 内置模块，把 JSON 注入 HTML
```

## 怎么加一个项目

1. 在 `data/projects.json` 加一条对象（字段照抄现有条目）
2. 在 `data/numbers.json` 加它用到的每个数字，写清口径与时间窗
3. 复制 `work/price-patrol.html` 改内容（或 `work/_template.html`）
4. 跑 `node assets/build.mjs`
5. 提交

**不需要碰任何 HTML 结构**——首页的精选区、项目区和口径总表都是从 JSON 生成的。

## 本地查看

直接双击 `index.html` 即可，不需要起服务器。所有资源都是相对路径，没有任何外部请求。

## 技术选择说明

**为什么不用 Astro / Next.js**：这个站只有 9 个页面、没有数据获取、没有用户状态、没有 SEO 复杂需求。上一个构建框架的代价是：依赖会腐化、三年后可能装不上、每次改一个字要等构建。而手写 CSS 的代价只是：多写几百行。

对一个**要在毕业后持续维护几年**的个人站点，「零依赖」比「开发体验」重要。
